# Isolated VOD identity test deployment

This is a private test adapter in VVHL-HUB, not the production website or an Elite Labs service. It runs the actual `docs/sql/vod_lg_identity.sql` resolver in PGlite, using a minimal compatibility schema from the regression suite. It does **not** certify compatibility with the full production Supabase schema or replace its authentication. It refuses Supabase URLs/service credentials, queue credentials and GM-profile connections at startup. Its database, jobs and media live on a new dedicated volume. Only health and the login page are public; API requests require a separate generated test access code. Codes and provider credentials must never be committed.

The five Python worker modules were copied from VVHL-HUB commit `e8ad201c094a88961153d40b140157ab3c0c05ec` (the existing restore test deployment). `worker/test_bootstrap.py` replaces the production bootstrap with loopback-only routes and no live ingestion or Supabase access. API keys are supplied through Railway references to the existing **test** worker's provider variables. Production secrets, session tokens and Twitch authentication are not copied. Independent AI request limits apply to this test worker.

`prepare.py` copies the final LG Client captures for Windsor 917960 and Gatineau 918009 and prepares all 12 actual participants per game. Registered gamertags are verified from those game sheets; historical CHEL/broadcast aliases require separate game-specific evidence. Both games have new test review IDs. Copied original period boundaries are documented in `reviews.json`; new results are provisional. Existing report IDs are provenance only, never used as destinations.

After the user completed LG verification, final October 27 London/Ottawa sheets were captured with twelve participants each. Both confirm LG 73707 (`l Setty l`) at center. The user's Kells/Bad News Kells attestation is applied only to those verified game contexts. These two entries replay reduced saved identity evidence without new video analysis or new performance claims; they are excluded from automatic fresh-video jobs. Identity-only marker rows cannot increase performance coverage. The user additionally confirmed the Setty label for Ottawa; all three aliases consolidate there. Other names remain unresolved until supported.

Start is idempotently blocked once a test job exists; it does not reset old jobs. A private resume route accepts failed test jobs only and preserves their saved chunks and reports. Completed jobs cannot be resumed or replaced through it. The API has no production publication, deletion or arbitrary URL route. Reconciliation groups resolved source names by the resolver's canonical key and keeps unresolved source rows. Coverage uses cited game and period reports, preserving their scope; repeating a citation is not independent evidence. All 12 participants appear in coverage, but roster-only or insufficient-evidence rows do not count as attributed observations and receive no invented rating. The complete worker response remains available for inspecting chunk evidence.

Follow-up test-worker fixes preserve trailing/leading gamertag punctuation and decode one in-window frame when a valid video tail is shorter than the normal six-second sampler. A generated two-second clip reproduces the original empty-frame failure; an out-of-range request still fails. These fixes apply only to the copied test worker, not production. Docker builds run the three Python regressions before the container is published.

Run `node --test test.cjs` with the pinned PGlite dependency. Deployment uses the repository root as Docker build context and `vod-identity-test/Dockerfile`. This prototype intentionally tests resolver + video-worker behavior separately from the full production management UI. Missing footage, unconfirmed historical aliases and lag-out boundaries remain blockers for other games.
